# Format Studio 功能提升方案

> 从 v0.01（Qt Widgets 原型）到 v0.02（Qt Quick 重写）的现状诊断、已落地能力与后续路线图。
> 对应代码：本仓库根目录；旧版参考 `D:\format studio\format-studio`。

---

## 0. 一句话结论

旧版是「三个页面 + 一个 FFmpeg 进程 + 换后缀」的原型：能跑，但转码不真、进度不可见、失败无原因、界面是系统控件堆叠。
v0.02 把**转换引擎**和**界面**同时重做：统一任务队列、真实编码参数、可观测进度、可重试错误，并用一套 QML 设计系统重画了整个界面。

| 维度 | v0.01 | v0.02 |
| --- | --- | --- |
| 转码真实性 | `-c copy` 只换容器 | 按目标格式选择编码器与码率 |
| 进度 | 无 | 百分比 / 倍速 / 剩余时间 |
| 并发 | 单进程，视频与音乐互相阻塞 | 1–4 个独立进程 |
| 错误处理 | 只有"转换失败" | 中文原因 + 单任务重试 |
| 界面 | 系统默认控件 | 自绘 QML 组件 + 深浅色 |
| 代码结构 | 3 套重复队列逻辑 | 单一 TaskModel + 单一调度器 |

## 1. 现状诊断（v0.01）

### 1.1 结构

`MainWindow` 一个类里塞了侧边栏、6 个页面、3 套任务队列、1 个 `QProcess`、全部槽函数，共 839 行；视频 / 音乐 / 图片三页的增删改查逻辑各写一遍。

### 1.2 功能缺陷

| # | 严重度 | 问题 | 位置 | 影响 |
| --- | --- | --- | --- | --- |
| 1 | 致命 | 视频用 `-c copy` 换容器 | `mainwindow.cpp:460` | mp4→avi/webm 等多数组合直接失败或产出不可播放文件 |
| 2 | 致命 | ffmpeg 只从 PATH 启动 | `mainwindow.cpp:463` | 用户机器没配环境变量就"点击无反应" |
| 3 | 高 | 丢弃 stdout，而进度在 stderr | `mainwindow.cpp:519-523` | 永远没有进度条、无法估计剩余时间 |
| 4 | 高 | "暂停"只置标志位 | `mainwindow.cpp:496-500` | 当前任务照常跑完，语义误导 |
| 5 | 高 | 删除行后 `rowIdx` 不重排 | `mainwindow.cpp:549-572` | 后续状态更新写到错误的行 |
| 6 | 高 | 输出目录为空时生成相对路径 | `mainwindow.cpp:416-418` | 文件落到进程工作目录，用户找不到 |
| 7 | 高 | 输出同名直接覆盖 | `mainwindow.cpp:418` | 数据丢失且无提示 |
| 8 | 中 | 视频页与音乐页共用一个 `QProcess` | `mainwindow.cpp:193`、`730` | 两个队列互相阻塞 |
| 9 | 中 | 图片转换在主线程 `QImage::load/save` | `mainwindow.cpp:825-826` | 大图批量时界面卡死 |
| 10 | 中 | 目标格式在"添加"时固化 | `mainwindow.cpp:416` | 加完文件再改下拉框无效 |
| 11 | 中 | 失败仅记录"转换失败" | `mainwindow.cpp:525-547` | 用户不知道是编码器缺失还是文件损坏 |
| 12 | 中 | 表格"预览"列从未填充 | `mainwindow.cpp:150-158` | 用户看不出文件是什么 |
| 13 | 低 | 文档页、设置页是空壳 | `mainwindow.cpp:200-207`、`364-371` | 侧边栏入口形同虚设 |
| 14 | 低 | 窗口固定 1050×680、无主题 | `mainwindow.cpp:26` | 高分屏与深色系统下观感差 |

### 1.3 界面问题

- 视觉层级只有"标题 + 输入框 + 表格 + 三个圆形按钮"，没有主操作与次操作之分，四个管理按钮（浏览/添加/删除/清空）与"输出目录"排在同一行抢注意力。
- 状态用纯文本塞进表格单元格，没有颜色、没有进度，长任务只能干等。
- 三页布局一模一样，却各维护一套控件；切页时队列状态互不相通。
- 无空状态、无拖放、无悬停反馈、无通知。

## 2. v0.02 已落地

### 2.1 功能矩阵

| 能力 | v0.01 | v0.02 |
| --- | --- | --- |
| 视频输出 | 7 种容器，`-c copy` | MP4 / MKV / MOV / WebM / AVI / GIF，按容器选编码器 |
| 音频输出 | 6 种扩展名，默认编码 | MP3 / M4A / WAV / FLAC / OGG / OPUS，明确码率 |
| 从视频提取音频 | 仅 MP3/WAV 项 | 任意视频任务可直接选 MP3/WAV 等 |
| 图片输出 | QImage 主线程保存 | PNG / JPG / WebP / BMP，独立进程 + 质量参数 |
| 进度 | 无 | 百分比 + 倍速 + 剩余时间（解析 `-progress pipe:1`） |
| 并发 | 串行 | 可配 1–4，每个任务独立进程 |
| 排队控制 | 假暂停 | 暂停排队 / 继续 / 停止 / 单任务取消 / 重试 |
| 元数据 | 无 | ffprobe：分辨率、编码、时长、采样率、声道 |
| 缩略图 | 无 | 自动截帧（视频第 25% 处，最多 3s） |
| 错误信息 | "转换失败" | 中文原因映射（文件损坏 / 权限 / 编码器缺失 / 参数无效） |
| 文件导入 | 文件对话框 | 文件对话框 + 全窗口拖放 + 文件夹递归扫描（最多 800 项） |
| 重复添加 | 无处理 | 按绝对路径去重 |
| 同名文件 | 覆盖 | 自动重命名 / 覆盖 / 跳过 |
| 设置持久化 | 无 | 输出目录、画质、并发、主题、默认格式 |
| 主题 | 固定浅色 | 深色 / 浅色 / 跟随系统 |
| 检查更新 | 无 | 比对 GitHub Release 版本，确认后下载并启动安装程序 |
| 反馈 | 无 | 内置反馈页（Bug / 功能期待），一键预填 GitHub Issue |
| 文档转换 | 空壳 | 规划页（v0.3） |

### 2.2 转码参数策略

| 目标 | 视频编码 | 音频编码 | 关键参数 |
| --- | --- | --- | --- |
| MP4 / MOV | libx264 | aac | CRF 18/23/28，preset medium（小体积用 veryfast），`+faststart` |
| MKV | libx264 | aac | 同上，无 faststart |
| WebM | libvpx-vp9 | libopus | CRF = 基础值 + 7，`-b:v 0`，`-row-mt 1` |
| AVI | mpeg4 | libmp3lame | `-q:v 3` |
| GIF | — | — | `palettegen` + `paletteuse`，12 fps，宽 480（小体积 320），无声 |
| MP3 | — | libmp3lame | 320k / 192k / 128k |
| M4A | — | aac | 同上 |
| WAV | — | pcm_s16le | 无损 |
| FLAC | — | flac | `-compression_level 8` |
| OGG | — | libvorbis | `-q:a 6` |
| OPUS | — | libopus | 128k |
| PNG / BMP | png / bmp | — | 单帧输出 |
| JPG | mjpeg | — | `-q:v` 2 / 4 / 7 |
| WebP | libwebp | — | quality 95 / 85 / 72 |

画质三档同时作用于视频 CRF 与音频码率，避免"选了高画质但音频还是 96k"的割裂感。

### 2.3 界面改版

**布局**：88px 侧边栏（品牌标 + 分类 + 主题切换 + 设置/关于）＋ 右侧单栏工作区。工作区自上而下是：页头 → 拖放区 → 输出设置卡 → 队列标题 → 任务卡列表 → 底部操作栏。用户视线从"要做什么"到"放什么"到"怎么转"到"结果如何"单向流动。

**视觉 token**（`Theme.qml`，深浅两套）：背景 / 卡片 / 下沉面三级灰阶，`border` 与 `borderStrong` 两级描边，品牌蓝 `#5B8DEF`（深）与 `#2F6BFF`（浅），成功 / 警告 / 危险各配柔和底色。圆角 16 / 10 / 7 三档，字号 9–26。

**组件清单**：

| 组件 | 职责 |
| --- | --- |
| `Icon` | 26 个线性 SVG，任意颜色（`QSvgRenderer` + `SourceIn` 着色） |
| `StudioButton` | 主按钮 / 次按钮 / 危险按钮，hover 过渡 |
| `IconButton` | 卡片内操作，带 Tooltip |
| `NavButton` | 侧边栏项，选中态左侧指示条 + 数字角标 + soon 标记 |
| `ThemeSwitch` | 侧边栏浅色/深色开关，图标随主题旋转过渡 |
| `Segmented` | 画质、并发、主题、同名策略的分段选择 |
| `FormatChip` | 输出格式胶囊，选中态高亮边框 |
| `DropZone` | 拖放区，拖入时变蓝并加粗边框 |
| `TaskCard` | 缩略图 + 信息 + 进度 + 格式下拉 + 状态胶囊 + 操作 |
| `Toast` | 右上角通知，四种语义色，3.2s 自动消失 |
| `EmptyState` | 空队列引导 |

**交互细节**：

- 全窗口 `DropArea`：拖到任何位置都能加文件，落在拖放区时额外高亮。
- 任务卡随状态换装：运行中蓝色描边、失败红色描边 + 错误行、完成绿色进度条。
- 队列底部渐隐，避免卡片被硬切；滚动条细线化。
- 设置改动即时生效并持久化，不需要"保存"按钮。
- 侧边栏固定提供一键深浅色切换（设置页的主题选项与之双向一致）。
- 队列操作按当前分类生效：开始转换只处理当前分类的等待任务，清空/清除已结束也只影响当前分类。

### 2.4 架构

```
QML (Theme / Main / ConvertPage / TaskCard …)
        │  绑定 role / 调用 Q_INVOKABLE
        ▼
ConverterBackend  ←  QSettings（持久化）
  ├─ TaskModel (QAbstractListModel，按 kind 过滤)
  ├─ 调度器：m_running < concurrency 时取队首
  ├─ QProcess × N：ffmpeg -progress pipe:1
  ├─ QProcess × 1：ffprobe -print_format json
  └─ QProcess × 1：截帧生成缩略图
```

**任务状态机**：`Queued → Running → Done / Failed / Canceled`，`Failed → Queued`（重试），`Queued → Skipped`（同名跳过）。

**关键取舍**：

- 用 `QProcess` 而不是链接 libav*：打包体积小、崩溃隔离、可直接复用系统/随包 FFmpeg；代价是需要解析文本进度。
- 任务存内存而非数据库：v0.02 追求启动即用；持久化在路线图中（v0.3）。
- 缩略图与探测异步执行，不阻塞 UI：即使拖入 100 个文件，界面仍可操作。

## 5. 风险与取舍

| 风险 | 现状 | 建议 |
| --- | --- | --- |
| 「暂停」语义 | 只暂停排队，当前文件继续 | 保留（FFmpeg 无法安全挂起），文案已明确"暂停队列" |
| 编码器缺失 | 假定 FFmpeg 为完整构建 | v0.3 增加 `-encoders` 探测，缺编码器时自动降级 |
| 长任务内存 | 只读进度行，stderr 仅保留尾部 4KB | 已可控 |
| 并发与磁盘 IO | 默认 2，机械盘建议 1–2 | 设置页已给出提示 |
| 文档转换 | 依赖外部 LibreOffice | 首次使用引导安装，检测失败时禁用入口 |
| 原生标题栏 | 窗口边框跟随系统主题 | 后续可换自绘标题栏统一深浅色 |

## 6. 建议的下一步

1. **先做 v0.3 的 1、2、3**：持久化、单任务参数、硬件加速——这三项直接决定"能不能当主力工具用"。
2. 再做 **输出命名模板 + 系统通知**，把批量体验补完整。
3. 文档转换单独排期，因为 LibreOffice 集成涉及安装包体积与进程管理，不建议与视频链路耦合。
4. 每个版本保留 `--smoke` 回归：新增格式时补一条用例，避免编码器参数回归。
